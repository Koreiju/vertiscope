| fact (pumap.py, umap-learn) | what it forces |
|---|---|
| `ParametricUMAP.update(X_new)` trains on `vstack(_raw, X_new)` with every earlier row pulled back to its old place | cost grows with ALL rows ever trained, not with the diff -- so the scope decides the cost of every later update |
| `transform` is the network's forward pass | a chunk trained on is placed exactly where training put it; no fit/transform frame mismatch in chunk scope |
| `_train` runs the whole set forward per step while rows <= 8,192, sampled batches beyond | the cost curve bends at 8,192 rows; chunk scope beyond it is out of any interactive budget |
| umap-learn has no update | the scope applies to the parametric engine only; umap-learn stays page scope |
| the triple centroid concatenates a frequency half chunk vectors lack | chunk scope requires the semantic centroid |

Candidates: (A) a fixed page-count threshold -- fails demand 1; (B) time the
first fit and extrapolate -- the first fit includes CUDA warm-up (22.9 s for
160 rows, against 3.3 s for 500 warm); (C) **a cost model seeded from the
measured curve and refined by every real update** -- chosen.
