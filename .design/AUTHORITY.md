# Authority census

Run 2026-09-28 with `node ~/.claude/skills/design-harness/scripts/authority.js .`
over 7,485 documents. The positive control could not run (nothing anchored in L0
yet), so the ranking was uninformative on its own; each document below was then
opened and judged. **Only the user's own words have authority.** Every reason is
a finding, kept so the next census does not re-decide it.

| document | why | what exactly |
|---|---|---|
| `docs/PLUGIN_GOAL.md` | The project rule (CLAUDE.md) makes it the verbatim record of the plugin: every direction the user gives is transcribed into it, dated, **before** it is decomposed. Own voice about the product ("our running plugin", "my described features") and addressed to the AI. | **Only the blockquoted (`> `) text.** The `*Read as:*` paragraphs and section prose are the AI's readings of it -- evidence of an interpretation, never authority. 1,104 quoted lines. |

How about this, perhaps we analyze this from the most convenient interface ...") from the REPL era, text not transcribed into the plugin record. | Blockquoted text only; 33 lines. The rest of the doc is out. |

## How this census can be wrong

- A user message given in a session whose transcript is gone and never
  transcribed into PLUGIN_GOAL would be missing entirely; only the census of
  *documents* is closed here, not of *sentences*.
- A `> ` block in PLUGIN_GOAL that quotes a web page or an error message rather
  than the user would be promoted by the extractor. Spot-check found none, but
  it has not been checked block by block.
