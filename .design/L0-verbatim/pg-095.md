## Reading

**This is my reading, not the requirement.** Several distinct claims: (a) targeted, feature-wise tests run plugin-in-the-loop against the specs and notes across the project history; (b) hidden deduplication the reference serializer caught (identical subtrees by Merkle signature) is missing now; (c) a recommended set of focused module tests, cheap in memory and context; (d) a formal, nested requirements/design model, separate from the code, integrating the whole design history, that localizes degradations -- this `.design/` tree; (e) the remaining pending requirements built and tested in the app; (f) the zoomed star-shaped 3D layout is a degradation to track and build properly; (g) GPU `update()` batch refits, observable, joined to the earlier pipeline steps; (h) overlays much lighter and near-untinted, fainter tint and border, a little brighter, still translucent; (i) the freeze; (j) memory profiling beside time profiling; (k) one full-pipeline harness in which rendering is an inlaid stage with its own time bound.

(d) is realized by this tree itself; (b) projects to [[L1.pg-062.dedup]]; (g) to [[L1.pg-062.refit]]; (h) to [[L1.pg-062.overlay]]; (i) to [[L1.pg-095.stability]]; (j)+(k) to [[L1.pg-095]] and [[L1.pg-062.render]].

**How this reading could be wrong.** "Smooth integral over the full design history" may ask for more than nesting: a model that weights later statements over earlier ones continuously, not only by explicit supersession. I have not built any weighting.
