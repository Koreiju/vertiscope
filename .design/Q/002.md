## What was found

The working store held **1,177** chunks for `discourse.julialang.org/latest`
this morning (`content_dups2.out`, read from the sidecar on 8788). Tonight it
holds **34** (`/page_map`, same sidecar, same workspace `build/corpus123`).

The mechanism, in the code:

- `sidecar.py`, capture route, `settle` branch: a page that settles is
  re-ingested whole -- `self.workspace.ingest(url, spine.trie)` -- with the
  comment "A settled page is complete: whatever the projector holds for it
  that the page no longer has is gone."
- `workspace.ingest` → `ingest_chunks(..., complete=True)` (the default).
- `graphstore.py`, the stale-removal step: with `complete`, every stored chunk
  of that URL not in the current render is `DETACH DELETE`d (`gone`).

Drains write with `complete=False` and delete nothing -- so between settles
the store GROWS (every regrouping of the list adds chunks beside the old
ones), and at each settle it SHRINKS to what the page holds now. Discourse
keeps ~30 rows after a fresh load, so a settle cut the forum to 34.

## Why it is a question and not a fix

[[Q.001]] asked what an open page should draw and offered *What's on the
page now*; the user chose **Everything stored** -- "keep drawing the page's
whole history". That ruling presumed the history is kept. The settle
deletion makes the store converge, after every settle, on exactly the option
the user declined. But deleting on settle was built deliberately (a page
that lost a section otherwise "stay[s] retrievable forever"), and whether the
STORE is a history or a map of the page now is a larger question than what
the pane draws.

## The options, and what each forces

| option | store after a settle | forces |
|---|---|---|
| **Keep history** (my reading of Q.001) | every chunk ever captured stays; the ones that left the page are marked (`left_at`), not deleted | subtree dedup becomes necessary, not optional: without it every regrouping of a moving list is kept forever ([[L1.pg-062.dedup]]); search must say which results are no longer on the page |
| Map of the page now (today) | only what the page holds | Q.001's "Everything stored" reduces to "what the page held at its last settle"; history exists only between settles |
| Keep history, bounded | chunks that left kept for N days / N visits | as the first, plus an eviction rule |

## Recommendation

Keep history, marked rather than deleted, and store each identical subtree
once (the reference serializer's Merkle signature). The two go together:
history without subtree dedup accumulates every regrouping; dedup without
history has nothing to dedup across.
